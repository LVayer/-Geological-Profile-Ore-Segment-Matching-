# 剖面地层自动识别与匹配实验系统

这是一个以**拒绝不可靠匹配**为优先的本地实验系统，不是经过真实地质资料验证的生产系统。全部环境、代码、数据、模型、日志和结果均位于项目根目录的三个分类文件夹中，运行时不需要联网。Jev 默认 mock，只有显式切换 live 才调用远程接口。

已实现并运行：规范导出图片的图例色块识别、实例区域提取、64 点边界、物理几何与接触拓扑、同岩性候选硬筛选、六种方法、冲突保留、JSON/CSV/HTML/PNG 输出、合成真值评测、独立数值测试。**并未实现可泛化到任意扫描图的自动图例文字解释和复杂构造解释**；这些情况使用人工确认图例或实例掩膜接入，不能当作自动识别成功。

## 快速运行

**图形界面：双击 `软件\启动界面.bat`。** 支持图片选择、剖面排序、框选绘图区和图例、方法选择、参数设置、自定义项目内输出目录、后台运行及结果打开。首次可点击「载入演示」直接体验。详见 [GUI 操作指南](docs/GUI_GUIDE.md)。命令行入口继续保留。

界面导入图片时自动建议主图矩形范围、贴合内容的曲线环与图例色块，并调用本地 Windows OCR 预填文字。图例在整张图片搜索，包含矩形主图内部的空白区域；识别地层时使用曲线内容掩膜，并单独排除图例框。剖面编辑器还可逐点勾画内容外轮廓和明确的非地层孔洞：直线段使用少量端点，曲线处增加采样点，完成后保存为闭合多边形。位于规则彩色色块序列内部的单个白色/空心色块，会在上下色块、间距、对齐和框内标记共同成立时作为低置信度候选给出，仍需人工确认。确认近白色图例后，封闭白色地质区域才允许参与分层；未确认时保留为未分类。双击剖面核对范围、岩性名称及物理坐标；低可靠度情况不会自动确认。实现见 `layout.py`、`ocr.py`。

`输入数据/实验/11-P11.JPG` 和 `12-P101.JPG` 已作为真实版面回归数据。当前自动结果分别为 1 个主图、11 个图例候选和 1 个主图、9 个图例候选，两图均包含 1 个通过排列推断的白色 Fe3 候选。人工核查范围保存在 `输入数据/实验/expected_layout.json`，可视化叠加图和机器报告保存在 `输出数据/experiment_validation/`；在“软件”目录执行 `python tools/validate_experiment_layout.py` 可重新生成。

大图识别采用内存受控的分块 CIELAB 判定，不再建立“全部像素 × 全部图例”的三维距离矩阵。默认工作像素上限为 750 万；JPEG 会优先在解码阶段缩放，实际坐标通过比例换算回物理范围。拓扑计算使用单张整数标签图和各层局部包围区，不再长期保存每层一张全图掩膜。被大图相对面积门槛拒绝的小碎片保持未分类，不会强制合并到邻层。界面可调整“识别工作像素上限”和“大图最小区域占比”；提高像素上限会增加细节和内存消耗。

在 PowerShell 中进入本目录：

```powershell

# 当前 .venv 已安装并验证；新机器需要先运行此命令
powershell -ExecutionPolicy Bypass -File .\setup.ps1
# 生成案例、训练合成 GNN、比较六种方法、导出审查页面

# 直接复用现有模型，重新比较
powershell -ExecutionPolicy Bypass -File .\run.ps1 benchmark
# 完整图片 -> 识别 -> 匹配
powershell -ExecutionPolicy Bypass -File .\run.ps1 pipeline `
  -InputFile ../输入数据/synthetic/images/split/manifest.json -OutputDir ../输出数据/image_pipeline
# 单独识别 / 导入人工实例掩膜
powershell -ExecutionPolicy Bypass -File .\run.ps1 recognize `
  -InputFile ../输入数据/synthetic/images/continuous/manifest.json -OutputDir ../输出数据/recognition
# 对已经确认的结构化剖面做匹配
powershell -ExecutionPolicy Bypass -File .\run.ps1 match `
  -InputFile ../输出数据/image_pipeline/sections.json -OutputDir ../输出数据/rematch
# 实际测试，临时文件和 pytest 缓存已限制在项目内
.\.venv\Scripts\python.exe -B -m pytest --junitxml=../输出数据/test-results.xml
```

也可使用 `.venv\Scripts\python.exe -B -m stratamatch --help`。所有输入文件也须复制到本目录内。路径越界或符号链接逃逸会报错。不要把 API Key 写入 JSON、代码或提交材料。

结果页可在软件内直接打开。基准剖面按“岩性族 + 地层实例”着色：同岩性颜色相近但不完全相同，不同岩性色差更大；目标剖面的对应地层复用基准层颜色，merge 使用多色条纹，未对应目标层使用灰色。每条关系显示为一个双列表格式按钮，可确认、否决、保留复核或新增修正关系。人工审查保存为 `manual_review.json`；只有人工确认的关系才能导出 `modeling_input_方法.json` 供三维建模。

## 图像输入的可靠性边界

识别采用三阶段顺序：先把自动/人工内容曲线当作最大范围，在线条完整路径上区分网格/钻孔与地质边界；再分别修复已确认的线状杂项和文字笔画；最后从清理后的地质颜色支撑重建实际内容域并提取地层。这里的地质边界按图像与拓扑证据分为“岩性分区边界”和“构造不连续边界”，不依赖图上写的是断层、界面或其他同义名称。粗钻孔会从检测中心线向两侧扩展到完整的浅色、低彩度通道；扩展半宽可在界面设置。初次修复要求相对方向两侧类别一致，交叉处再以整段杂项通道重连。最终对已经确认的技术线和标签区域使用已核对图例类别做最近可靠区域分区回填，不能留下把地层切断的白缝；多种地层的重建交界另存为红色复核线。普通空白和不确定路径不参与回填，所以不会用全图填洞抹掉真实尖灭、构造不连续或 split。每次任务输出杂项图和未分类诊断图；青色是已接受杂项，绿色是受保护地质界面，紫红色是不能可靠决定的线。

剖面编辑器可填写“人工粗略地层数”。该数字只用于结果偏差告警，不参与面积阈值、区域保留、合并或删除。审计记录包含估计值、自动识别值、容许范围及是否落入范围，避免用粗略人工计数反向强制分割结果。

1. 支持 PNG、JPG/JPEG、TIFF。多页 TIFF 必须配置 `page`，不能无声忽略后续页面。
2. 需要明确绘图区 ROI、公共物理坐标范围、同一坐标基准和单位、沿空间顺序递增的 station。**不会把两张不同坐标图简单归一化后当作已配准。** 未确认配准时只输出复核建议。
3. 通过图例色块位置取色，或显式 RGB 映射到规范岩性名称。`verified=true` 表示岩性文字已人工确认；未确认者为 UNKNOWN，禁止连续匹配。
4. 色彩比较采用浮点 CIELAB 距离、第二候选间隔和最小连通域。近色、同色不同岩性、未分类像素不会被猜测填满。当前色差是 CIE76，不是 CIEDE2000。
5. 自动杂项处理后，`exclude_polygons` 仍可人工补充文字/注释区；`fault_polygons` 标出断层后，对涉及该剖面的自动判断保守降为复核。不会声称能自动区分所有黑色边界、文字和断层。
6. 同色接触地层无法从颜色分开；纹理是唯一判据时、复杂填充纹理/断层/褶皱/扫描图，使用人工实例 mask。没有经验证的纹理分类器，不强行命名。
7. JPEG 受色彩渗漏影响，当前最高识别质量为 0.75，低于自动接受阈值。PNG/TIFF 是推荐输入。像素级测试显示当前 JPEG 示例 IoU 约 87%–95%，不会用盲目膨胀掩膜来“修复”边界。

参阅 [输入与标注规范](docs/INPUT_FORMAT.md)。

## 共享特征与地质约束

每个地层保存 lithology、order、centroid、area、perimeter、extent/width、mean_thickness、thickness_variation、完整 thickness_profile、dip、upper/lower_boundary、outline、outline_rings、上下邻层、其他接触层、local_topology、quality 和异常标志。边界默认 64 点，使用弧长重采样；原始实例标签 NPY 保留，便于重新提取边界。

坐标约定：x 向右，y 是向下增加的深度。面积、长度使用输入物理单位；厚度是**垂向厚度**，dip 是剖面**视倾角**，不是三维真倾角。列内多段区域会降低质量，不能把折叠地层的包络当作可靠上下边界。外轮廓为像素中心曲线，面积按像素单元计数，两种离散定义会有约一像素的差别。

候选特征包括位置、厚度比、面积比、去平移形状差、绝对边界差、方向差、层序差、上下邻层岩性集、接触邻层岩性集、拓扑度差。岩性不同或 UNKNOWN **直接排除，连 GNN/Jev/Laya 都不会收到这种匹配候选**。这是唯一的地质硬筛选。位置、上下邻层岩性、形态的默认软权重相对较高，其余更低；位置/边界/厚度变化再大也只会触发 `uncertain`，不再删除同岩性候选。所有权重可在界面调整，并随结果写入 `matching_policy`。这些数值是保守先验，尚未用真实标注校准。

全局优化完成后，重新禁止每条拟接受关系并求最优替代解，检查其稳定性；同时检查识别质量、几何突变、上下邻层变化及真正映射的接触边冲突。前序匹配只产生最大 0.08 的有限代价修正，永远不能覆盖当前岩性和地质规则。已降为不确定的关系不作为可靠上下文。

没有可靠目标不等于尖灭。仅当出现端部变薄、目标完整、两侧锚定层对应且在目标接触、无合法候选、配准可靠时，才提出 `pinch-out`。它仍是二维证据推断，不是排除断层/侵蚀后的地质定论。

## 六种方法

| 方法 | 实现与运行状态 | 主要局限 |
|---|---|---|
| DTW / DP | 分段序列动态规划，匹配、缺口、1:N/N:1 状态转移；已运行 | 要求层序单调和组内连续，不适合倒转褶皱 |
| 图匹配 | 地层候选超边二元变量、未匹配变量、精确覆盖和非交叉约束的全局 MILP；已运行 | 是特定约束的超图优化，不是通用二次图同构求解器；拓扑还需后验审查 |
| Markov | semi-Markov 分段序列模型，持续长度先验、地质发射代价、Viterbi 和 log-space 前后向边际；已运行 | 概率来自工程能量，不是地质标注拟合或校准概率 |
| GNN | 候选超边构成图、归一化邻接、两层 GCN + 原始特征残差，反向传播和保存/加载；已训练运行 | 仅合成训练，全部建议需要复核，不能声称真实高精度 |
| Jev | Venice Decisions API 的 state/questions/noul 请求、超时、响应校验、限长、可选重试和 mock/fallback；已离线测试 | 无真实 Key，未做在线调用；mock 是地质代价回退，不是 Jev 推理 |
| Laya | 与 Jev 共用同一 state/questions；支持可选本地 Python 权重或 TypeSafe-compatible HTTP；已离线测试 | 未下载本地权重、未做真实推理或地质校准；默认全部复核 |

组大小默认最大 3，可配置 1–4；many-to-many 没有独立求解器。跨越不同岩性内部层的组合强制复核。任一剖面超过 80 个实例时自动进入“大实例保守模式”：保留全部实例，只生成同岩性空间近邻候选，优先保留一对一候选，并在候选预算内加入连续相邻的 split/merge 组合；跳过逐条 MILP 替代解重算，所有关系强制 `manual_review/uncertain`。默认最多 1200 条候选，数量、筛选统计和警告写入结果，不再因超过 80 层直接中止。MILP 没有证明最优时不接受部分解。

详细公式、假设及来源见 [算法说明](docs/METHODS.md)。

## 当前测试与指标

详见 [实施报告](docs/IMPLEMENTATION_REPORT.md) 和 `outputs/benchmark/metrics.json`。36 组案例来自 12 类场景 × 3 个测试种子，包含 81 个源地层、57 条真值对应边，以及 split/merge/pinch-out 各 3 个事件。训练使用种子 20–27，测试 1001–1003；**仅隔离种子，场景生成族仍相同**，不能替代跨区域独立测试。

DTW、图匹配和 Markov 在这套小样本上结果相同：45 条正确自动接受边、0 条错误接受边、12 条漏匹配；真值边召回 78.95%，split/merge/pinch-out 各 3/3；45/81 个源地层自动接受（包括尖灭），覆盖率 55.56%。应拒判的 36 个源地层全部拒判。

GNN、Jev 与 Laya 当前自动接受数为 0，接受精度为 null，**不能把“0 错误”解释为准确率 100%**。每种方法的原始建议均有 57 条正确边、12 条错误边；这说明拒判规则是必要的，也说明当前数据不足以比较方法优劣。

评测严格区分：接受精度 = 正确接受边 / 全部接受边；正确匹配率（召回）= 正确接受边 / 真值边；错误率 = 错误接受边 / 全部接受边；漏匹配包括拒判的真值边；split/merge 使用完整成员集合事件级判定。无分母返回 null，不回填为 0 或 1。

## 接入真实数据、Jev 与 Laya

先用十几对人工确认的规范剖面建立识别基线，随后应使用不同区域/项目的独立数据验证。建议同时提供：原始无损图、图例与标准岩性字典、坐标轴/比例尺/剖面位置、实例掩膜、断层/不整合标注、逐层对应关系（包含无对应和无法判断）及证据说明。不要把同一地层在相邻图片的切片分散到训练和测试。

真实标注 GNN：`run.ps1 train -InputFile data/real/partitions.json`。输入必须有 train/validation/test，按 survey_group 隔离，并声明完整标注；新权重生成在 `models/gnn_annotations.npz`。该路径只完成训练接入和泄漏校验，仍需独立验证、校准和人工审查，不会自动解除 GNN 的复核限制。

Jev：在当前 PowerShell 会话中设置 `$env:VENICE_API_KEY`，修改 `config/default.json` 中 `jev.mode` 为 `live`，检查 endpoint/model 后运行。请求会包含地层几何及上下文。当前无实际在线验证；API beta 契约变化时只需修改 `jev.py` 的 `payload()` / `parse()`。mock/fallback 在输出 provenance 中明确记录，失败不会悄悄标成真实模型成功。

Laya：界面可选 mock、HTTP 或 Python。HTTP 默认指向本机 `127.0.0.1:8791/v1/systemone`；Python 模式需要另行安装 `laya` 并首次下载权重。系统没有自动安装或下载大型权重。Laya 与 Jev 调用相同的候选事实、地质规则、问题文本与 criteria，只有模型/传输/响应字段不同。无论模型报告多高置信度，在真实地质标注验证前仍为 `manual_review`。

## 目前最影响精度的问题

- 无真实专家标注，无法确定代价、拒判阈值和分数校准，也无法统计真实误匹配率。
- 图例语义、重复同岩性层、纹理型图案及黑色线条用途的识别需要人工信息。
- 不同剖面必须具有可比较的物理坐标/方向；弯曲测线、不同剖面走向、三维产状不能由图片自动推断。
- 地层排序来自几何位置，不等于已知地质年代顺序；复杂褶皱/断层仅能保守标注复核。
- 接触判断采用有限像素间隔；极薄夹层和边界线宽变化会影响拓扑。
- 多对多、侵蚀与断层导致的消失、真厚度、正式 HRBF/三维体建模尚未实现；输出边界和关系可作为后续接口。
